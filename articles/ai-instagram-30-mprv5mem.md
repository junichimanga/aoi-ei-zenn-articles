# AIにInstagramを30日間任せた観測ノート

## 結論から言う

30日間、毎日の動画と投稿を機械に任せた。
フォロワーは増えた日もあったし、再生数が半分以下に落ちた日もあった。
「自動化したら楽になった」で終わる話ではない。
これはその観測記録だ。成功談ではない。

---

## 何をやったか

毎日の投稿を、以下の流れで機械に任せた。

1. AIアバターが台本を読み上げた動画を生成する
2. その動画に字幕を自動で合成する
3. キャプションとハッシュタグを自動で生成する
4. 毎朝7時に自動投稿する

人間がやったことは、最初に「今日のテーマ」を決める5分だけ。
あとは放置した。

使った仕組みを日常語に翻訳すると：

| 技術的な呼び名 | 日常語での説明 |
|---|---|
| HeyGen | 顔と声のあるAIが台本を読み上げてくれるサービス |
| OpenAI Whisper | 音声から文字を起こして字幕をつける仕組み |
| Remotion | コードで動画を作って書き出せるツール |
| Instagram Graph API | プログラムからInstagramに投稿できる公式の窓口 |

これらを組み合わせて、「テーマを渡したら動画が完成して投稿まで終わる」パイプラインを作った。

## 30日間の数値を時系列で出す

筆者の環境での観測値。条件：フォロワー数百〜千程度の小規模アカウント、リール中心運用。

| 期間 | 平均再生数 | 平均保存数 | 特記事項 |
|------|-----------|-----------|---------|
| 1〜7日目 | 約180 | 3〜5 | 自動投稿スタート直後 |
| 8〜14日目 | 約310 | 8〜12 | 字幕あり動画が反応を得はじめる |
| 15〜21日目 | 約140 | 2〜4 | 急落週（原因は後述） |
| 22〜28日目 | 約260 | 6〜9 | 手動介入後に回復傾向 |

数値は週単位の平均値。個別投稿では1桁再生の日もあれば、1本だけ2,100再生を超えた日もある。ばらつきが大きい。平均値だけ見ると現実を見誤る。

---

## 数値が落ちた日の原因記録

### 15〜21日目：急落の原因

この週だけ平均再生数が半分以下に落ちた。
感覚で「アルゴリズムのせい」にして終わりにしたくなる。
が、ログを掘ったら原因は3つ出てきた。

**原因1：投稿時間が1時間ずれていた**
自動投稿の設定が、サーバー時間とローカル時間の差で1時間ずれていた。
毎朝7時のつもりが8時投稿になっていた。
再現性は確認中だが、時間帯の変化が反応に影響した可能性がある。

**原因2：字幕テキストが長すぎた**
この週は1文が長い台本を試した。
字幕が画面の40〜50%を覆う状態になり、映像が見えにくくなった。
保存数が落ちたのはこれが一因だったと見ている。

**原因3：テーマが抽象的すぎた**
「思考を変えよう」「本質を見ろ」系のテーマは、数値の反応が薄かった。
具体的な操作手順や実例を見せる内容のほうが、保存数が伸びる傾向があった。
あくまで筆者の観測範囲での傾向。再現性の検証は続けている。

---

## 自動のままにした部分 vs 手動に戻した部分

### 自動のまま継続

- 毎朝7時の定時投稿
- ハッシュタグの選定（候補20個から上位10個を自動選択）
- キャプションの下書き生成

### 手動に戻した

**テーマ決定**
機械に丸投げすると抽象的なテーマに偏った。
前日夜に人間が1行メモを書く運用に切り替えた。

**字幕の長さ確認**
1文15文字以内を目安に、投稿前に目視確認するようにした。
確認に要する時間は1〜2分。これは省略できなかった。

**投稿後の最初のコメント**
投稿後30分以内にコメントを1件入れると、その後の反応が変わる傾向があった。
再現性はまだ確認中だが、この作業だけは手動に残している。

完全自動化の夢は一旦下ろした。
「9割自動・1割確認」が今の落とし所。

## コードで見る仕組み（関心がある人向け）

自動投稿の核心部分の実装。Node.js環境で実際に動くコード。

```js
// Instagram Reelの自動投稿フロー（抜粋）
const axios = require('axios');

async function postReel({ videoUrl, caption, accessToken, accountId }) {
  // Step1: メディアコンテナを作成
  const { data: container } = await axios.post(
    `https://graph.facebook.com/v19.0/${accountId}/media`,
    null,
    {
      params: {
        media_type: 'REELS',
        video_url: videoUrl,
        caption: caption,
        access_token: accessToken,
      },
    }
  );

  const containerId = container.id;

  // Step2: アップロード完了をポーリングで待つ
  let statusCode = 'IN_PROGRESS';
  while (statusCode === 'IN_PROGRESS') {
    await new Promise((r) => setTimeout(r, 5000)); // 5秒待機
    const { data: statusData } = await axios.get(
      `https://graph.facebook.com/v19.0/${containerId}`,
      {
        params: { fields: 'status_code', access_token: accessToken },
      }
    );
    statusCode = statusData.status_code;
    if (statusCode === 'ERROR') throw new Error('メディア処理に失敗しました');
  }

  // Step3: 公開
  const { data: published } = await axios.post(
    `https://graph.facebook.com/v19.0/${accountId}/media_publish`,
    null,
    {
      params: { creation_id: containerId, access_token: accessToken },
    }
  );

  return published.id;
}
```

Step2のポーリングを省略すると、動画処理が終わる前に公開しようとしてエラーになる。
最初にやった失敗のひとつ。

## ハマりどころ3つ

**1. アクセストークンは切れる**
Instagramの認証情報には有効期限がある。
切れると投稿が黙って止まる。エラーログを見ていないと気づかない。
30日運用中、1回だけこれで投稿が途切れた。定期的な更新処理が必要。

**2. 動画ファイルはURLで渡す**
Instagramへの投稿は「公開URLを渡す」方式。
ローカルファイルのパスは受け付けない。
動画を外部ストレージにアップロードしてURLを取得する手順が必ず挟まる。
この順番を間違えると投稿が通らない。

**3. 機械生成の文章は口調がブレる**
キャプションをAIに生成させると、日によって文体がバラバラになった。
「断定的・短文・体言止め」という口調ルールをプロンプトに毎回明示しないと崩れる。
口調はブランドの一部。ここだけは機械任せにしない部分になった。

---

## まとめ

30日間の観測から言えること。

- 投稿の「実行」は機械に任せられる
- 「何を言うか」と「口調」は人間が管理する
- 数値が落ちた日には必ず原因があった。感覚より記録が正確
- 完全放置より「9割自動・1割確認」のほうが崩れにくい

自動化は「楽になる道具」ではなく「確認の量を変える道具」だった。
どこに5分を使うかを設計するのが本当の仕事。

非効率は罪。あなたもやってみて。
