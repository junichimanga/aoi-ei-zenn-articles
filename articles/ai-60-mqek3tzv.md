# AIに毎日メルマガを書かせた60日間の実験ログ

## 結論

60日間、ChatGPT-4oとClaudeにメルマガ本文を書かせ続けた。
個人リスト規模のため統計的有意差は主張できない。それでも、ひとつの傾向は見えた。

AI代筆率を上げた週は、開封率が下がった。例外なく。

「楽になる」は正しい。「読まれ続ける」は別の話。

失敗例の方が多いから、先に書く。

---

## 前提: 環境と運用ルール

**スタック:**

- 配信: Fumi Mail Studio（自作WordPressプラグイン + MCP連携）
- AI: ChatGPT-4oとClaude Sonnet 4.5を週替わりで使用
- 配信頻度: 毎日1本（60日中、欠配7日）
- リスト規模: 個人メルマガリスト。統計的有意差を主張できる規模ではない。傾向の記録として読んでほしい

**60日間変えなかったルール:**

1. テーマと書き出し1文（冒頭フック）は人間が書く
2. 本文300〜400字をAIに生成させる
3. 「冷たい」と感じた文章は手で直す
4. 直した箇所と理由をその日のメモに残す

**用語の定義:**

「AI代筆率」= 最終送信本文の文字数のうち、AI生成テキストから変更せずに残った文字数の割合。文字ベースのdiffで計測（後述のスクリプトを参照）。

「手直し率」= 1 − AI代筆率。

60日全体の平均AI代筆率: 約53%。週によって20%〜90%まで変動した。

---

## 観測した傾向

W1〜W3（代筆率20〜70%）では開封率は横ばいか緩やかな上昇傾向。
W4で代筆率を意図的に90%まで引き上げた。開封率が60日間の最低を記録し、同週に解約が増えた。

ただし、W4は以下の交絡要因も重なっていた。

| 要因 | W4の状況 |
|:--|:--|
| 曜日・配信タイミング | 変更なし |
| テーマ難易度 | やや高め（API連携の話が多かった） |
| 件名の書き手 | AIが生成した件名を3本使用（平常時は0本） |
| 時期 | GW明け直後 |

開封率低下の原因をAI代筆率だけに帰属させるのは過剰。件名の変化、テーマ難易度、時期が絡んでいる。「複数の要因が重なった週に数字が落ちた」が正確な記述。

W5以降、件名を人間が書き、代筆率を55%前後に戻した。開封率は回復した。これも複合要因だが、傾向として記録する。

## 実際に使ったコード

毎日の本文生成を自動化したNode.jsスクリプト。

```js
// scripts/generate_newsletter_body.js
// ※このスクリプトはバッチ処理用にAPIキーを直接利用している。
// 対話的な用途は Claude Code（MAXプラン）経由でも同等の生成が可能。
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic(); // ANTHROPIC_API_KEY を .env から読む

const CHARACTER_VOICE = `
あなたは「蒼井詠（あおい えい）」として書く。
ルール:
- 断定的・クール・体言止め。感情を表に出さない
- 短文。小学生にもわかる語彙
- 禁止語: 「ぜひ」「〜してみましょう」「〜できます！」「きっと〜」
- 末尾は必ず「あなたもやってみて。」で締める
`.trim();

/**
 * メルマガ本文を生成する
 * @param {string} topic  - テーマ（例: "ChatGPTの音声入力を業務に使う"）
 * @param {string} opener - 書き出し1文（人間が書く）
 * @returns {Promise<string>} 生成された本文（300〜400字）
 */
export async function generateNewsletterBody(topic, opener) {
  const response = await client.messages.create({
    model: "claude-sonnet-4-5",
    max_tokens: 700,
    messages: [
      {
        role: "user",
        content: `${CHARACTER_VOICE}

テーマ: ${topic}
書き出し（この1文に続ける形で書く。書き出し自体は出力しない）:
${opener}

条件:
- 続きの本文を 300〜400 字で書く
- 根拠のない数値効果（◯%削減など）は書かない
- URLは含めない
`,
      },
    ],
  });

  const text = response.content[0];
  if (text.type !== "text") throw new Error("unexpected response type");
  return text.text;
}
```

```bash
# CLI から単体で動かす場合
node scripts/generate_newsletter_body.js \
  "Claude MCPで社内ツールをつないだ話" \
  "AIを使う・使わないより、どこにつなぐかで決まる。"
```

生成した本文はFumi Mail StudioのMCPツール `fms_create_block_newsletter_draft` に渡してドラフト保存。送信前に必ず目視確認する運用にしている。

### AI代筆率の算出スクリプト

「何をもって代筆と判定するか」を定義しないと、この実験の数字に意味がない。文字ベースのdiffを使った計測スクリプトを公開する。

```js
// scripts/measure_ghostwrite_rate.js
import { diffChars } from "diff";

/**
 * AI生成テキストと最終送信テキストを比較し、AI代筆率を返す
 * @param {string} aiGenerated  AI生成テキスト（生成直後・手直し前）
 * @param {string} finalSent    実際に送信したテキスト
 * @returns {number} 0〜1 の代筆率（1 = 全文AI代筆、0 = AI文字が1文字も残っていない）
 */
export function measureGhostwriteRate(aiGenerated, finalSent) {
  const changes = diffChars(aiGenerated, finalSent);
  let unchanged = 0;
  let total = 0;
  for (const part of changes) {
    if (!part.added) total += part.value.length;               // AI生成文字数の合計
    if (!part.added && !part.removed) unchanged += part.value.length; // そのまま残った文字数
  }
  return total === 0 ? 0 : unchanged / total;
}

// 使用例
// const rate = measureGhostwriteRate(aiText, sentText);
// console.log(`AI代筆率: ${Math.round(rate * 100)}%`);
```

各メールの送信後、AI生成ログと送信済み本文を渡してこのスクリプトを走らせた。これが週次代筆率の実測値の根拠になっている。

## ハマりどころ: 「冷たさ」の正体と3つのパターン

### パターン1: 構造は正しいが温度がゼロ（W3〜W4に多発）

論理の流れは正しい。でも読んで「送りたくない」と感じる。その感覚と数字は一致していた。

**Before（Claude Sonnet 4.5生成）:**

```
AIツールは非常に多く存在しており、どれを選べばよいか
迷われる方も多いのではないかと思います。まずは気軽に
試してみることをおすすめします。自分に合ったツールを
見つけることが大切です。
```

**After（手直し後）:**

```
ツールが多すぎる、は言い訳。
選ぶ基準がないだけ。
今日、1つだけ触ってみて。
```

文字数: 88字 → 33字。手直しの9割は「削ること」。追加はほぼしない。

---

### パターン2: 「あなた」の過剰摂取（W5に集中）

蒼井詠の締め定型は「あなたもやってみて。」。AIはこれを本文中にも増殖させる。1通に「あなた」が6回出現した日があった。

**Before（ChatGPT-4o生成）:**

```
あなたの業務に合ったツールを選ぶことが大切です。
ぜひあなたも一度試してみてください。
きっとあなたの仕事が楽になるはずです。
あなたにとっての正解は、使いながら見つかるものです。
```

**After（手直し後）:**

```
ツールは使いながら選ぶ。
迷う時間の方が無駄。
```

「あなた」はメール本文で1回以内。ルール化した。

---

### パターン3: Claudeの留保地獄（全期間を通じて散発）

ChatGPT-4oは「鼓舞しすぎ」で冷たい。Claude Sonnet 4.5は「丁寧すぎ」で冷たい。方向が逆なだけで、どちらも蒼井詠じゃない。

| モデル | 冷たさの方向 | 主な削除対象 |
|:--|:--|:--|
| ChatGPT-4o | 前向きすぎ・鼓舞系 | `できます！` `きっと〜` `ぜひ〜` |
| Claude Sonnet 4.5 | 丁寧すぎ・留保系 | `〜かもしれません` `〜と思います` `〜でしょう` |

**Before（Claude Sonnet 4.5生成）:**

```
自動化ツールを導入すれば、作業時間が短縮できる
可能性があります。ただし、すべての方に同じ効果が
あるとは言えないかもしれません。まずは小さなタスクから
試してみるのも一つの方法かと思います。
```

**After（手直し後）:**

```
自動化は、やった人だけが速くなる。
小さいタスクから始める。順番はそれだけ。
```

Claude版の手直しは「かもしれません」「と思います」を断定に変える作業が中心だった。プロンプトを強化すれば減るが、ゼロにはならなかった。

---

## まとめ

60日間で見えたこと。

- AI代筆率が高い週に開封率が下がる傾向があった（個人リスト・複合要因あり。因果断定は禁物）
- 「冷たさ」はモデルごとに方向が違う。削り方の型もモデルごとに変わる
- 手直しの中心は「削ること」。追加より除去が効く
- テーマと書き出し1文を人間が書けば、品質の底は維持できる
- 代筆率を上げるなら、件名と書き出しだけは絶対に人間が書く

完全自動化は無理。でも「人間が書く量」は減った。60日で自分が直接書いた文字数は実験前の半分以下になった。

今夜送る1通から、書き出しの1文だけ自分で書いてみて。それだけで、読者への温度が変わる。
